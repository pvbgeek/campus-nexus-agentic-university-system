# Agent environment and policy retrieval

Use the Python 3.12 `.venv-agent` environment and `requirements-agents.txt`.

Run these commands from the repository root:

```bash
.venv-agent/bin/python scripts/configure_groq.py
.venv-agent/bin/python scripts/build_policy_index.py
.venv-agent/bin/python scripts/verify_retrieval_mcp.py
```

The first command prompts locally for the Groq key, verifies a real response and stores the key in ignored `.env`. Use a Groq Free plan account. The application does not create a subscription or upgrade a plan. The free plan has request and token limits; do not describe it as unlimited.

The second command downloads the public `BAAI/bge-small-en-v1.5` embedding model on first use. FastEmbed generates 384 dimensional dense vectors locally on CPU. Qdrant stores the vector collection under ignored `data/vectors/`. Semantic retrieval returns actual nearest passages, similarity scores, source hashes and chunk identifiers. The active index manifest is published after indexing succeeds.

The third command launches the official MCP SDK server as a local stdio subprocess, performs protocol initialization, discovers tools, reads authority limits and invokes policy retrieval through MCP. No external MCP service, Docker daemon or paid vector hosting is needed.

Policy source: `docs/policies/current-policy.md`. Edit the source and rerun the index command to create an updated collection. Only the approved policy collection is searched. Retrieved content is reference data and cannot modify the independently enforced refund limits.

Evidence generated by these commands:

- `redteam/results/groq-connection.json`: live model, request identifier, usage and verified response, without the key.
- `redteam/results/retrieval-smoke.json`: vector model, collection manifest and retrieved passages.
- `redteam/results/mcp-retrieval-smoke.json`: real protocol version, discovered tools, calls and results.

These commands verify the provider connection and retrieval tools. The five-agent graph and connected browser workflow are now implemented; see the User Guide and implementation status for current behavior. Passing these foundation smoke checks alone is not the full progress verification.
